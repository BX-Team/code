---
icon: Package
title: Your first pack
description: Create a pack, add mods, publish it and install it, all from the terminal.
---

This walks through the whole cycle with the CLI. The launcher's developer mode does the same steps with buttons.

::steps
:::step{title="Create the project"}
In an empty folder (ideally a git repository):

```bash
riven init --mc 1.21.1 --loader neoforge
```

This writes `riven.json` for the newest NeoForge build of 1.21.1 and adds riven's working folders to `.gitignore`. Leave out `--mc` for the latest release; pin a loader build with `--loader neoforge@21.1.77`.
:::

:::step{title="Add content"}
```bash
riven add sodium
riven add create
riven add https://github.com/owner/mod/releases/latest
riven add ./jars/private-mod.jar
```

Each `add` resolves the dependencies, shows the plan and writes `riven.json`. Configs go into `overrides/common/`, `overrides/client/` or `overrides/server/` as plain files.
:::

:::step{title="Check it"}
```bash
riven check
riven list --tree
```

`check` reads every jar's own metadata and reports missing dependencies, incompatibilities and loader mismatches. It exits with a failure code when it finds a problem, so it fits CI.
:::

:::step{title="Build and publish"}
```bash
riven keygen                 # once per pack
riven build --channel stable
riven deploy
```

`build` writes a signed release into `dist/`; `deploy` commits `dist/` to the `gh-pages` branch and prints the install link, such as `gh:owner/pack`.
:::

:::step{title="Install it"}
Players paste the link into **New instance → Link or file**. A server runs:

```bash
riven install --side server --dir /srv/mc --headless gh:owner/pack
```
:::
::

Next release: change content, `riven bump`, `riven build`, `riven deploy`. Installed instances pick it up on their next launch.
