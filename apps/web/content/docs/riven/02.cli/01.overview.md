`riven` with no arguments opens the launcher. With a subcommand it runs in the terminal and never opens a window — on Windows it writes to the terminal it was started from.

```bash
riven --help          # every command
riven add --help      # one command
riven --version
```

## Commands

| Command | What it does | Page |
| ------- | ------------ | ---- |
| `init`, `add`, `remove`, `update` | Create a pack and change its content | [Authoring](/docs/riven/cli/authoring) |
| `pin`, `unpin`, `side`, `group` | Fine-tune entries | [Authoring](/docs/riven/cli/authoring) |
| `list`, `why`, `check`, `bump`, `import` | Inspect, validate, version, migrate | [Authoring](/docs/riven/cli/authoring) |
| `keygen`, `build`, `publish`, `deploy`, `export` | Make and ship releases | [Releases](/docs/riven/cli/releases) |
| `install`, `status`, `trust`, `self-update` | Install packs and keep things current | [Installing](/docs/riven/cli/installing) |

## The project

Authoring and release commands work on `riven.json`, found in the current directory or the nearest parent — run them anywhere inside the pack repository. The file is rewritten deterministically (fixed field order, sorted entries), so its git diffs stay readable. Don't edit it by hand.

A pack repository looks like this:

```
my-pack/
  riven.json
  icon.png              optional, shown by launchers
  overrides/
    common/             config/…, kubejs/…, defaultconfigs/…
    client/             options.txt, shaderpacks/…
    server/             server-only files
  local/                jars added from disk
  dist/                 riven build output (git-ignored)
  .riven/               cache (git-ignored)
```

## Global options

| Option | Effect |
| ------ | ------ |
| `--json` | Print one JSON document to stdout instead of human output. Progress and prompts are turned off. |
| `-h`, `--help` | Help for the command. |
| `-V`, `--version` | The Riven version. |

`--json` is accepted after any subcommand: `riven list --json`, `riven install --json …`.

## Prompts

Authoring commands print what they changed (`+` added, `~` updated, `-` removed); use `riven update --dry-run` to look first. `riven install` shows its plan and asks before applying — unless `--yes`, `--headless`, `--json` or a non-terminal stdin says nobody is there to answer.

## Logs

```bash
RIVEN_LOG=debug riven install gh:owner/pack
```

`RIVEN_LOG` takes `tracing` filters such as `info`, `debug` or `riven_sync=trace`. Account tokens never appear in logs.

## Exit codes

| Code | Meaning |
| :--: | ------- |
| `0` | Success. |
| `1` | An error, a cancelled prompt, or `riven check` found problems. |
| `2` | Invalid arguments. |

Errors go to stderr; with `--json` they are printed to stdout as `{"error": "…"}`.

## Data folders

| | Linux | Windows | macOS |
| --- | --- | --- | --- |
| Data (store, instances, Java) | `~/.local/share/riven` | `%APPDATA%\Riven` | `~/Library/Application Support/Riven` |
| Config (settings, keys, trusted keys) | `~/.config/riven` | `%APPDATA%\Riven` | `~/Library/Application Support/Riven` |

Downloads live once in a content-addressed store (`store/sha512/…`) and are hard-linked into game folders.
