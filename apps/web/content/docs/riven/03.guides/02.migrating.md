title: Migrating a pack
description: Move an existing Modrinth or packwiz pack to Riven.
---

## From a .mrpack

```bash
mkdir my-pack && cd my-pack
riven import mrpack ../MyPack-1.2.0.mrpack
riven check
```

Files listed in the archive keep their Modrinth links; jars the exporter embedded in `overrides/` are looked up on Modrinth by hash and linked instead of copied. Configs land in `overrides/common/`, `overrides/client/` or `overrides/server/`.

## From packwiz

```bash
riven import packwiz ../old-pack                           # folder
riven import packwiz ../old-pack/pack.toml
riven import packwiz https://example.com/pack/pack.toml    # hosted pack
```

- Modrinth metafiles become Modrinth entries.
- CurseForge metafiles become direct links to the CurseForge CDN, which serves files without an API key.
- Files the index marks `preserve` keep that flag.
- Optional mods go into the `optional` group.

You can also go through Modrinth: `packwiz modrinth export`, then `riven import mrpack`.

## After importing

1. `riven check` — fix what it reports, usually a missing dependency: `riven add <slug>`.
2. Look at the summary of files that could not be identified; add them with `riven add <url>` or keep the copies under `local/`.
3. `riven update` later moves link and local entries over to Modrinth whenever Modrinth hosts the exact same file.
4. Commit `riven.json`, `overrides/` and `local/`; build and deploy as in [Your first pack](/docs/riven/getting-started/first-pack).
