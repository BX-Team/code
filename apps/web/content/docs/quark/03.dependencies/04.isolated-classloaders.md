title: Isolated Class Loaders
description: Load libraries into their own class loaders, apart from the plugin and the server.
---

An isolated class loader holds libraries that your plugin's class path never sees. Its parent is the JDK's platform class loader, so code inside it sees the JDK and its own JARs, but neither your plugin nor the server.

## When to Use Them

- **A second version of a library**: the plugin uses one version, a feature needs another.
- **Optional features**: drivers or tools that are loaded only when a server owner turns the feature on.
- **Tools you call reflectively**: a compiler, a script engine, anything with a small entry point.

For the usual "the server ships another version" problem, [relocation](/docs/quark/dependencies/relocation) is simpler: relocated classes are on the plugin's class path and you use them directly.

## Named Class Loaders

```java
List<Dependency> dependencies = List.of(Dependency.of("org.xerial", "sqlite-jdbc", "3.46.1.0"));

// creates the class loader "sqlite" if it does not exist and loads into it
libraryManager.loadDependenciesIsolated("sqlite", dependencies, List.of());

IsolatedClassLoader loader = libraryManager.getIsolatedClassLoader("sqlite");
Class<?> driverClass = loader.loadClass("org.sqlite.JDBC");
```

Or create the loader first and load into it:

```java
IsolatedClassLoader loader = libraryManager.createNamedIsolatedClassLoader("sqlite");
libraryManager.loadDependencies(loader, dependencies, List.of());
```

`getIsolatedClassLoader(id)` returns `null` for an unknown id.

## The Global Class Loader

Every library manager also has one shared isolated class loader, for libraries several features use:

```java
IsolatedClassLoader global = libraryManager.getGlobalIsolatedClassLoader();
libraryManager.loadDependencies(global, dependencies, List.of());
```

## From the Gradle Manifest

The whole manifest can go into an isolated class loader instead of the plugin's class path:

```java
// into a named class loader, created if needed
libraryManager.loadFromGradleIsolated("runtime");

// or into one you created
libraryManager.loadFromGradle(loader);
```

## Using Isolated Classes

Your plugin's code is compiled against types the isolated class loader can't see, so you can't simply cast an object from it to your own interface. Use JDK types and reflection at the boundary:

```java
IsolatedClassLoader loader = libraryManager.getIsolatedClassLoader("sqlite");

// JDBC drivers register through java.sql, which both sides share
Driver driver = (Driver) loader.loadClass("org.sqlite.JDBC").getDeclaredConstructor().newInstance();
Connection connection = driver.connect("jdbc:sqlite:" + dataFile, new Properties());
```

```java
// any other class: call it reflectively
Class<?> gsonClass = loader.loadClass("com.google.gson.Gson");
Object gson = gsonClass.getDeclaredConstructor().newInstance();
String json = (String) gsonClass.getMethod("toJson", Object.class).invoke(gson, Map.of("key", "value"));
```

`IsolatedClassLoader` can also take JARs and classes you provide:

```java
loader.addPath(Path.of("extensions/extra.jar"));
Class<?> defined = loader.defineClass("com.example.Generated", generatedClassBytes); // the stream is closed for you
```

## Combining with Relocation

Relocations work in isolated class loaders too. Load the classes by their relocated names:

```java
libraryManager.loadDependencies(
        loader,
        List.of(Dependency.of("com.google.code.gson", "gson", "2.11.0")),
        List.of(Relocation.of("com.google.gson", "com.example.isolated.gson"))
);

Class<?> gsonClass = loader.loadClass("com.example.isolated.gson.Gson");
```

## Closing

An isolated class loader is a `URLClassLoader` and keeps its JARs open. Close loaders you no longer need, for example when a feature is turned off on reload:

```java
loader.close();
```
