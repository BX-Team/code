`quark-dependency` resolves Maven dependencies with their transitive dependencies, downloads them into the plugin's data folder and adds them to the plugin's class loader. Add it with `quark { modules(QuarkModule.DEPENDENCY) }`.

## Creating a Library Manager

`LibraryManager.builder()` creates a manager. `plugin(this)` lets the adapter on the class path decide how JARs are added to your plugin, so the same code works on every platform:

::code-group
```java [Paper / Bukkit]
public final class MyPlugin extends JavaPlugin {
    @Override
    public void onLoad() {
        LibraryManager libraryManager = LibraryManager.builder()
                .plugin(this)
                .dataDirectory(getDataFolder().toPath())
                .build();
        libraryManager.loadFromGradle();
    }
}
```
```java [Velocity]
@Plugin(id = "myplugin", name = "MyPlugin", version = "1.0.0")
public final class MyPlugin {
    @Inject
    public MyPlugin(@DataDirectory Path dataDirectory) {
        LibraryManager libraryManager = LibraryManager.builder()
                .plugin(this)
                .dataDirectory(dataDirectory)
                .build();
        libraryManager.loadFromGradle();
    }
}
```
```java [BungeeCord]
public final class MyPlugin extends Plugin {
    @Override
    public void onLoad() {
        LibraryManager libraryManager = LibraryManager.builder()
                .plugin(this)
                .dataDirectory(getDataFolder().toPath())
                .build();
        libraryManager.loadFromGradle();
    }
}
```
::

Load dependencies as early as possible: in `onLoad()` on Bukkit and BungeeCord, in the constructor on Velocity. A class that uses a library must not be loaded before the library is on the class path, so keep such code out of fields and static initializers of your main class.

::callout{type="info" title="Paper plugins"}
  Plugins with a `paper-plugin.yml` keep their libraries in a separate class loader. `plugin(this)` handles this for you, nothing else to configure.
::

### Builder Options

| Method | Description |
|--------|-------------|
| `dataDirectory(Path)` | **Required.** Libraries are stored in `<dataDirectory>/libs` in Maven layout |
| `plugin(Object)` | Uses the platform adapter to add JARs to the plugin's class loader |
| `classLoader(URLClassLoader)` | Adds JARs to this class loader instead |
| `appender(ClassLoaderAppender)` | Full control over how JARs are added |
| `librariesDirectory(String)` | Name of the libraries folder, `libs` by default |
| `logger(QuarkLogger)` | Logger for downloads and warnings, for example `platform.logger()` |
| `resources(ResourceProvider)` | Where the manifest is read from, the plugin's class loader by default |

Without `plugin`, `classLoader` or `appender` the manager can still download dependencies and load them into [isolated class loaders](/docs/quark/dependencies/isolated-classloaders), but not into the plugin's class path.

::callout{type="info" title="Platform library managers"}
  `BukkitLibraryManager`, `PaperLibraryManager`, `VelocityLibraryManager` and `BungeeLibraryManager` from Quark 1.x still exist in the adapters and work the same way. New code should use the builder: it is the same on every platform.
::

## Loading from Gradle

With the [Gradle plugin](/docs/quark/gradle-plugin/configuration), `loadFromGradle()` reads `META-INF/quark/manifest` from your jar and loads everything in it, with its repositories and relocations:

```java
libraryManager.loadFromGradle();
```

Gradle already resolved the dependency tree when you built the plugin, so Quark downloads exactly the listed JARs and does not read their POMs again. A plugin without a manifest loads nothing.

```java
// true if the plugin was built with the Gradle plugin and declares quark dependencies
if (libraryManager.hasGradleMetadata()) {
    libraryManager.loadFromGradle();
}

// the parsed manifest, if any
libraryManager.getManifest().ifPresent(manifest -> {
    manifest.dependencies().forEach(dependency -> getLogger().info("Runtime library: " + dependency));
});
```

## Loading Dependencies by Hand

Without the Gradle plugin, or for libraries you only need sometimes, load dependencies yourself. Add repositories first, see [Repositories](/docs/quark/dependencies/repositories):

```java
libraryManager.addGoogleMavenCentralMirror();

// by coordinates
libraryManager.loadDependency("com.google.code.gson", "gson", "2.11.0");

// from a coordinates string, group:artifact:version[:classifier]
libraryManager.loadDependency("org.xerial:sqlite-jdbc:3.46.1.0");

// several at once, resolved together
libraryManager.loadDependencies(List.of(
        Dependency.of("com.zaxxer", "HikariCP", "7.1.0"),
        Dependency.fromCoordinates("org.mariadb.jdbc:mariadb-java-client:3.5.1")
));

// with relocations
libraryManager.loadDependencies(
        List.of(Dependency.of("com.google.code.gson", "gson", "2.11.0")),
        List.of(Relocation.of("com.google.gson", "com.example.libs.gson"))
);
```

Hand-loaded dependencies are resolved transitively: Quark reads their POMs, including parent POMs and their `dependencyManagement`, and loads what they depend on.

### The Dependency Builder

```java
Dependency dependency = Dependency.builder()
        .groupId("com.example")
        .artifactId("library")
        .version("1.0.0")
        .classifier("all")                                        // optional
        .fallbackRepository("https://repo.example.com/releases/") // tried after the global repositories
        .build();

libraryManager.loadDependency(dependency);
```

`Dependency` is immutable. `withVersion(...)`, `withClassifier(...)` and `withFallbackRepository(...)` return a copy.

## Resolution

### Versions

When the same library is requested in several versions, Quark keeps one:

- the version you declared yourself always wins;
- otherwise the **newest** requested version is used.

Versions are compared the way Maven does, so `1.10` is newer than `1.9` and `2.0.0` is newer than `2.0.0-rc1`.

### Transitive Options

```java
libraryManager
        .maxTransitiveDepth(2)                        // root dependencies have depth 0
        .excludeGroupIds("org.slf4j", "log4j")        // never load these groups
        .excludeArtifacts("*:commons-logging")        // groupId:artifactId, * is a wildcard
        .skipOptionalDependencies(true)               // default
        .skipTestDependencies(true)                   // default
        .includeDependencyManagement(false);          // default
```

`optimizeDependencyDownloads()` applies a set of defaults in one call: depth 3, no optional or test dependencies and no `javax.servlet`.

These options apply to hand-loaded dependencies. The Gradle manifest is loaded as it is, configure exclusions in your build script instead.

## Checking What Is Loaded

```java
Dependency gson = Dependency.of("com.google.code.gson", "gson", "2.11.0");
if (libraryManager.isDependencyLoaded(gson)) {
    // ...
}

// every loaded dependency and its JAR
libraryManager.getLoadedDependencies().forEach((dependency, path) ->
        getLogger().info(dependency.toShortString() + " -> " + path));

// counts of repositories, dependencies and isolated class loaders
getLogger().info(libraryManager.getStats().toString());
```

## Error Handling

Loading throws `LibraryManager.LibraryLoadException` when a dependency cannot be resolved, downloaded or added. Decide whether your plugin can run without it:

```java
try {
    libraryManager.loadFromGradle();
} catch (LibraryManager.LibraryLoadException e) {
    getLogger().severe("Could not load libraries: " + e.getMessage());
    getServer().getPluginManager().disablePlugin(this);
}
```

A malformed manifest throws `ManifestException`. This only happens with a hand-edited manifest or one written by a newer, incompatible Gradle plugin.

## Logging

Downloads are reported through the manager's logger. Pass your own with `logger(...)` and change the level when you debug resolution:

```java
LibraryManager libraryManager = LibraryManager.builder()
        .plugin(this)
        .dataDirectory(getDataFolder().toPath())
        .logger(platform.logger())
        .build();

libraryManager.setLogLevel(LogLevel.DEBUG);
```
