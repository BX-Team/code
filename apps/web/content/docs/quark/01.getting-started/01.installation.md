## With the Gradle plugin (recommended)

The Quark Gradle plugin adds the platform adapter and the modules you ask for, writes the dependency manifest and relocates Quark into your plugin's package. It needs the [Shadow](https://gradleup.com/shadow/) plugin in the same project.

::steps
:::step{title="Apply the plugins"}
Apply Quark next to Shadow in the project that builds the plugin jar:

::::code-group
```kotlin [Gradle Kotlin]
plugins {
    java
    id("com.gradleup.shadow") version "9.1.0"
    id("org.bxteam.quark") version "2.0.0"
}

group = "com.example"
```
```groovy [Gradle Groovy]
plugins {
    id 'java'
    id 'com.gradleup.shadow' version '9.1.0'
    id 'org.bxteam.quark' version '2.0.0'
}

group = 'com.example'
```
::::

The project `group` matters: Quark is relocated to `<group>.libs.quark`. Without a group the build fails and asks you to set one.
:::

:::step{title="Choose the platform and modules"}
Tell Quark which server the plugin runs on and which modules it needs:

::::code-group
```kotlin [Gradle Kotlin]
import org.bxteam.quark.gradle.QuarkModule
import org.bxteam.quark.gradle.ServerPlatform

quark {
    platform = ServerPlatform.PAPER
    modules(QuarkModule.DEPENDENCY, QuarkModule.CONFIG)
}
```
```groovy [Gradle Groovy]
quark {
    platform 'paper'
    modules 'dependency', 'config'
}
```
::::

`platform` adds the adapter (`quark-paper` here), every module adds its artifacts. All versions come from the Quark BOM, so they always match the plugin version.
:::

:::step{title="Declare runtime dependencies"}
Libraries in the `quark` configuration are not shaded. They go into the manifest and are downloaded when the plugin starts:

::::code-group
```kotlin [Gradle Kotlin]
import org.bxteam.quark.gradle.relocate

dependencies {
    quark("com.zaxxer:HikariCP:7.1.0")
    quark("com.google.code.gson:gson:2.11.0") { relocate = true }
}
```
```groovy [Gradle Groovy]
dependencies {
    quark 'com.zaxxer:HikariCP:7.1.0'
    quark('com.google.code.gson:gson:2.11.0') { ext.relocate = true }
}
```
::::

The `quark` configuration also extends `compileOnly`, so you can use these libraries in your code right away.
:::

:::step{title="Build the plugin"}
Build the shaded jar as usual:

```bash
./gradlew shadowJar
```
:::
::

Read [Gradle Plugin](/docs/quark/gradle-plugin/configuration) for every option of the `quark { }` block.

## Modules

| `QuarkModule` | Groovy name | Adds |
|---------------|-------------|------|
| `DEPENDENCY` | `dependency` | `quark-dependency` - runtime downloads, relocation, isolated class loaders |
| `CONFIG` | `config` | `quark-config` and `quark-config-yaml`, plus `quark-config-serdes-bukkit` on Paper, Folia and Bukkit |
| `CONFIG_VALIDATOR` | `config-validator` | `quark-config-validator` |
| `LOGGER` | `logger` | `quark-logger` - SLF4J and Log4j adapters |
| `UPDATE` | `update` | `quark-update` |

The adapter, `quark-common` and `quark-platform-api` come from `platform` and are always there.

::callout{type="info" title="CONFIG without DEPENDENCY"}
  The YAML format runs on snakeyaml-engine, which is not shipped with Quark. With the `DEPENDENCY` module it is downloaded when the first config loads. Without it, add `implementation("org.snakeyaml:snakeyaml-engine:3.1.1")` so it is shaded into the plugin. See [YAML backend](/docs/quark/configs/creating-configs#yaml-backend).
::

## Without the Gradle plugin

If you build with Maven or don't want the Gradle plugin, add the BX Team repository and pick modules through the BOM.

### Repository

::code-group
```kotlin [Gradle Kotlin]
repositories {
    maven("https://repo.bxteam.org/releases")
}
```
```groovy [Gradle Groovy]
repositories {
    maven { url 'https://repo.bxteam.org/releases' }
}
```
```xml [Maven]
<repository>
    <id>bx-team-releases</id>
    <url>https://repo.bxteam.org/releases</url>
</repository>
```
::

### Dependencies

::code-group
```kotlin [Gradle Kotlin]
dependencies {
    implementation(platform("org.bxteam.quark:quark-bom:2.0.0"))
    implementation("org.bxteam.quark:quark-paper")
    implementation("org.bxteam.quark:quark-dependency")
}
```
```groovy [Gradle Groovy]
dependencies {
    implementation platform('org.bxteam.quark:quark-bom:2.0.0')
    implementation 'org.bxteam.quark:quark-paper'
    implementation 'org.bxteam.quark:quark-dependency'
}
```
```xml [Maven]
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.bxteam.quark</groupId>
            <artifactId>quark-bom</artifactId>
            <version>2.0.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.bxteam.quark</groupId>
        <artifactId>quark-paper</artifactId>
    </dependency>
    <dependency>
        <groupId>org.bxteam.quark</groupId>
        <artifactId>quark-dependency</artifactId>
    </dependency>
</dependencies>
```
::

::callout{type="error" title="Relocate Quark"}
  Without the Gradle plugin you have to shade Quark and relocate `org.bxteam.quark` into your own package yourself (for example with the Shadow or the Maven Shade plugin). Two plugins with different Quark versions on one server would otherwise load each other's classes. Keep `META-INF/services` files merged, Quark finds its adapters through them.
::

Without the Gradle plugin there is no dependency manifest, so load libraries by hand with `LibraryManager#loadDependency(...)`, see [Loading Dependencies](/docs/quark/dependencies/loading-dependencies#loading-dependencies-by-hand).
