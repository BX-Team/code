`platform.scheduler()` runs tasks for your plugin with one API on every server. Delays and periods are `Duration`s, every method returns a `TaskHandle`.

## Basic Usage

```java
Scheduler scheduler = platform.scheduler();

// off the server thread, as soon as possible
scheduler.async(() -> database.save(data));

// on the next tick of the sync thread
scheduler.sync(() -> Bukkit.broadcastMessage("Saved!"));

// on the sync thread after a delay
scheduler.later(() -> player.sendMessage("5 seconds passed"), Duration.ofSeconds(5));

// on the sync thread every minute, the first run after 10 seconds
TaskHandle autosave = scheduler.repeating(this::autosave, Duration.ofSeconds(10), Duration.ofMinutes(1));

// the async variants
scheduler.asyncLater(this::cleanup, Duration.ofMinutes(5));
scheduler.asyncRepeating(this::refreshCache, Duration.ZERO, Duration.ofSeconds(30));
```

On Bukkit-based servers durations are rounded up to whole ticks (50 ms).

## Cancelling

```java
TaskHandle handle = scheduler.repeating(this::tick, Duration.ZERO, Duration.ofSeconds(1));

handle.cancel();
handle.isCancelled(); // true

// every task this scheduler started for the plugin
scheduler.cancelAll();
```

Call `cancelAll()` in `onDisable()` if your plugin can be reloaded.

## Getting Values from the Sync Thread

`callSync` runs a computation on the sync thread and returns a `CompletableFuture`, for example to read world state from an async task:

```java
scheduler.async(() -> {
    PlayerData data = database.load(uuid);

    scheduler.callSync(() -> Bukkit.getPlayer(uuid))
            .thenAccept(player -> {
                if (player != null) {
                    scheduler.sync(() -> apply(player, data));
                }
            });
});
```

The future completes exceptionally when the task throws or is cancelled.

`isSyncThread()` tells whether the current thread is the sync thread. It is always `false` on proxies.

## Which Thread Is "Sync"?

| Platform | `sync`, `later`, `repeating` run on |
|----------|-------------------------------------|
| Bukkit, Paper | The main server thread |
| Folia | The **global region** thread |
| Velocity, BungeeCord | The proxy's task pool, proxies have no main thread |

## Folia

Folia ticks regions of the world on different threads. The global region thread is safe for world-independent things: plugin state, game rules, console commands, broadcasts. It must not touch entities or blocks.

For those, `PaperScheduler` (from `PaperPlatform#scheduler()`) has overloads that run on the thread owning the entity or the location:

```java
PaperScheduler scheduler = PaperPlatform.create(this).scheduler();

// on the thread that owns the player
scheduler.sync(player, () -> player.setHealth(20));

// on the thread that owns the region around the location
scheduler.sync(location, () -> location.getBlock().setType(Material.STONE));

// delayed and repeating variants
scheduler.later(player, () -> player.sendMessage("Welcome back!"), Duration.ofSeconds(3));
scheduler.repeating(entity, () -> entity.setGlowing(!entity.isGlowing()), Duration.ZERO, Duration.ofSeconds(1));

// check before touching an entity from the current thread
if (scheduler.isOwnedByCurrentThread(player)) {
    player.setHealth(20);
}
```

A task bound to an entity is skipped when the entity is removed before it runs, and a repeating one stops.

On Paper the same calls simply run on the main thread, so one jar works on both servers. On Paper versions without the region scheduler API every task goes through the Bukkit scheduler.

::callout{type="warn"}
  `cancelAll()` does not cover tasks bound to an entity or a location on Folia. Keep their handles and cancel them yourself.
::

## Executor

`asExecutor()` returns an `Executor` that runs every task with `async(...)`. Pass it to code that expects a plain executor, such as `CompletableFuture.supplyAsync(..., executor)` or Quark's update providers.

```java
Executor executor = platform.scheduler().asExecutor();
CompletableFuture.supplyAsync(() -> database.load(uuid), executor);
```
