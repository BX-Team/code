`quark-platform-api` describes the server a plugin runs on: its type and version, the plugin's data folder and logger, and a scheduler. Every adapter implements it, so code written against `Platform` works on Paper, Folia, Bukkit, Velocity and BungeeCord alike.

The platform API comes with the adapter, `quark { platform = ... }` adds it.

## Creating the Platform

Each adapter has a factory:

::code-group
```java [Paper / Folia]
Platform platform = PaperPlatform.create(this);
```
```java [Bukkit]
Platform platform = BukkitPlatform.create(this);
```
```java [Velocity]
@Plugin(id = "myplugin", name = "MyPlugin", version = "1.0.0")
public final class MyPlugin {
    private final Platform platform;

    @Inject
    public MyPlugin(ProxyServer server, Logger logger, @DataDirectory Path dataDirectory) {
        this.platform = VelocityPlatform.create(server, this, dataDirectory, logger);
    }
}
```
```java [BungeeCord]
Platform platform = BungeePlatform.create(this);
```
::

On Velocity, pass the injected SLF4J `Logger` when you create the platform in the constructor. The short form `VelocityPlatform.create(server, this, dataDirectory)` looks the plugin up in the plugin manager, which only knows it after the constructor, so use it from `ProxyInitializeEvent` on.

`PaperPlatform.create(...)` returns a `PaperPlatform`, whose `scheduler()` is a `PaperScheduler` with the [Folia overloads](/docs/quark/platform/scheduler#folia).

### Detecting the Platform

Code shared between several plugins, or a plugin that ships more than one adapter, can let Quark find the right one:

```java
Platform platform = Platform.detect(this);
```

Every adapter registers a provider; the one that supports the running server wins (Paper beats Bukkit on a Paper server). If none does, `detect` throws a `PlatformException` that names the adapter to add. On Velocity use `VelocityPlatform.create(...)`, the plugin instance alone is not enough to build the platform there.

## What a Platform Offers

```java
platform.id();             // "paper", "bukkit", "velocity", "bungee"
platform.type();           // PlatformType.PAPER
platform.type().isProxy(); // true on Velocity and BungeeCord
platform.dataDirectory();  // the plugin's data folder
platform.logger();         // the plugin's logger as a QuarkLogger
platform.scheduler();      // see the Scheduler page
platform.version();        // server and Minecraft version
```

### Versions

`PlatformVersion` holds the server software, its version and the Minecraft version:

```java
PlatformVersion version = platform.version();

version.name();       // "Paper"
version.server();     // the server software version
version.minecraft();  // 1.21.8, null on proxies

if (version.isMinecraftAtLeast("1.20.5")) {
    // use data components
}
```

Versions are `SemanticVersion`s from `quark-common`. They parse leniently (`v1.2`, `1.21`) and compare by [Semantic Versioning](https://semver.org) rules:

```java
SemanticVersion current = SemanticVersion.parse("1.4.0");
current.isNewerThan(SemanticVersion.parse("1.3.9"));   // true
current.isAtLeast(SemanticVersion.of(1, 4, 0));         // true
```

## Platforms in Library Code

Quark's own libraries (configs, the update checker, the dependency manager) never depend on `Platform`. They take plain JDK types instead, and the platform bridges them:

```java
// an Executor for anything that runs asynchronously
Executor executor = platform.scheduler().asExecutor();

// the plugin's logger for anything that logs
UpdateChecker checker = new UpdateChecker(UpdateProvider.modrinth("my-plugin"), "1.0.0");
checker.checkAndLog(platform.logger());
```

Follow the same rule in your own shared code: take an `Executor`, a `Path` and a `QuarkLogger`, and keep platform classes in the plugin's main module.
