Quark 2.0 turns the dependency manager into one module of a small framework. The dependency manager itself works as before and its packages are still `org.bxteam.quark`, but the artifacts, the Gradle plugin and the setup changed.

## What Changed

| Quark 1.x | Quark 2.0 |
|-----------|-----------|
| One artifact per platform (`org.bxteam.quark:bukkit`) with the dependency manager inside | An adapter per platform (`quark-bukkit`) plus optional modules; the dependency manager is `quark-dependency` |
| `quark { platform = "paper" }` | `quark { platform = ServerPlatform.PAPER; modules(QuarkModule.DEPENDENCY) }` |
| Quark stayed in `org.bxteam.quark` unless you relocated it | Quark is always relocated to `<group>.libs.quark` |
| `quark/dependencies.txt`, `repositories.txt`, `relocations.txt` in the jar | One manifest, `META-INF/quark/manifest` |
| `new BukkitLibraryManager(this)` | `LibraryManager.builder().plugin(this)...` (the old classes still work) |
| Relocation with `me.lucko:jar-relocator` | Quark's own relocator, only ASM is downloaded |
| Sponge and Fabric adapters | Not available yet, stay on 1.3 |
| `org.bxteam.runserver` as a separate plugin | Dev servers in `quark { devServer { } }` |

## Updating the Build Script

::steps
:::step{title="Update the plugin version"}
Quark 2.0 needs Java 17, Gradle 8.14 or newer and the Shadow plugin.

```kotlin
plugins {
    id("com.gradleup.shadow") version "9.1.0"
    id("org.bxteam.quark") version "1.3.0" // [!code --]
    id("org.bxteam.quark") version "2.0.0" // [!code ++]
}
```
:::

:::step{title="Set the platform and add the dependency module"}
`platform` is an enum now, and the dependency manager is a module you ask for:

```kotlin
import org.bxteam.quark.gradle.QuarkModule // [!code ++]
import org.bxteam.quark.gradle.ServerPlatform // [!code ++]

quark {
    platform = "paper" // [!code --]
    platform = ServerPlatform.PAPER // [!code ++]
    modules(QuarkModule.DEPENDENCY) // [!code ++]
}
```

In Groovy `platform 'paper'` and `modules 'dependency'` work.
:::

:::step{title="Remove the old Quark dependency"}
If you added the platform artifact by hand, remove it. The Gradle plugin adds the adapter and modules in the matching version:

```kotlin
dependencies {
    implementation("org.bxteam.quark:paper:1.3.0") // [!code --]
    quark("com.google.code.gson:gson:2.11.0")
}
```
:::

:::step{title="Set the project group"}
Quark is relocated to `<group>.libs.quark`. If the project has no `group`, set one, or choose the package with `quark { quarkPackage = "my.plugin.libs.quark" }`.

If you relocated Quark yourself with `relocate("org.bxteam.quark", ...)`, remove that rule.
:::
::

`repositories { }`, `includeProjectRepositories()`, `relocate(...)` and the `quark` configuration work as in 1.x.

## Updating the Code

The platform library managers still exist, so this keeps working after the build script is updated:

```java
BukkitLibraryManager libraryManager = new BukkitLibraryManager(this);
libraryManager.loadFromGradle();
```

The builder is the new way and is the same on every platform:

```java
BukkitLibraryManager libraryManager = new BukkitLibraryManager(this); // [!code --]
LibraryManager libraryManager = LibraryManager.builder() // [!code ++]
        .plugin(this) // [!code ++]
        .dataDirectory(getDataFolder().toPath()) // [!code ++]
        .build(); // [!code ++]
libraryManager.loadFromGradle();
```

On Velocity the constructor needed the logger and the plugin manager; the builder only needs the data directory:

```java
libraryManager = new VelocityLibraryManager<>(this, logger, dataDirectory, pluginManager); // [!code --]
libraryManager = LibraryManager.builder().plugin(this).dataDirectory(dataDirectory).build(); // [!code ++]
```

### Changed and Removed API

| 1.x | 2.0 |
|-----|-----|
| `getGradleMetadata()` | `getManifest()`. The old method is deprecated and will be removed |
| `addMavenCentral()` | Still deprecated, use `addGoogleMavenCentralMirror()` |
| `Relocation#getPattern()`, `getRelocatedPattern()` | `Relocation` is a record: `pattern()`, `relocatedPattern()` |

## Things to Check

- **Rebuild every plugin.** Quark 2.0 reads only the new manifest. A jar built with the 1.x Gradle plugin loads no dependencies at runtime.
- **Version conflicts are resolved differently.** When a library is requested in several versions, the newest one wins, and versions you declare yourself always win. 1.x could keep an older version. Gradle's choice from the manifest is loaded as it is.
- **Relocated libraries are cached again.** The relocator changed, so relocated JARs from 1.x are not reused. The first start downloads ASM and relocates once more.
- **Look at the warnings.** Quark now warns when the server ships its own copy of a library you load. Mark that dependency with [`relocate = true`](/docs/quark/dependencies/relocation).
