All of these commands work on the `riven.json` of the current directory or its nearest parent.

## riven init

Creates `riven.json` in the current directory.

```bash
riven init                                  # latest release, newest NeoForge
riven init --mc 1.21.1 --loader fabric
riven init --mc 1.21.1 --loader neoforge@21.1.77
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `--mc <version>` | latest release | Minecraft version |
| `--loader <name[@version]>` | `neoforge` | `vanilla`, `fabric`, `quilt`, `neoforge` or `forge`, optionally with a build |

The pack id and name come from the folder name. riven's working folders (`dist/`, `.riven/`, `exports/`) are added to `.gitignore`.

## riven add

Adds content and every dependency it needs, then writes `riven.json`.

```bash
riven add sodium                                    # Modrinth slug, id or search
riven add https://modrinth.com/mod/iris              # Modrinth project or version page
riven add owner/repo --source github                 # newest GitHub release that fits
riven add https://github.com/owner/repo/releases/tag/v2.1.0
riven add https://edge.forgecdn.net/files/…/mod.jar  # any direct file link
riven add ./jars/private.jar                         # a local file
```

| Option | Description |
| ------ | ----------- |
| `--source <modrinth\|github\|url\|local>` | Where the query points; guessed from it when left out |
| `--asset <pattern>` | GitHub asset name, `*` matching the version: `mymod-neoforge-*.jar` |
| `--side <client\|server\|both>` | Where the entry is installed; otherwise from the platform or the jar |
| `--group <id>` | Put the entry into an optional group |
| `--pin` | Keep this version on `riven update` |

How it resolves:

- **Modrinth** versions are filtered by the pack's Minecraft version and loader; the newest of any channel wins.
- **Dependencies** come from the platform and from the jar's own metadata (`fabric.mod.json`, `quilt.mod.json`, `META-INF/neoforge.mods.toml`, `META-INF/mods.toml`), version ranges included.
- **GitHub** releases are tried newest first until a jar fits the pack; the asset name becomes a pattern, so later releases match too.
- **Local** files outside the repository are copied into `local/`.
- The kind (mod, resource pack, shader pack, data pack) is read from the file.

Mods that are not on Modrinth, including CurseForge ones, can be added by their direct download link.

## riven remove

```bash
riven remove create
riven remove create --keep-deps
```

Removes an entry and the dependencies nothing else needs any more. `--keep-deps` keeps them.

## riven update

```bash
riven update --dry-run      # see what would change
riven update                # every `follow` entry
riven update sodium iris    # only these
riven update mymod --url https://example.com/mymod-1.3.jar
```

| Option | Description |
| ------ | ----------- |
| `--dry-run` | Print the plan without writing `riven.json` |
| `--url <url>` | Point a URL entry at a new file |

`update` finds newer Modrinth versions, newer fitting GitHub releases and changed local files, and adds new dependencies they bring. Pinned entries stay. It also moves GitHub, URL and local entries over to Modrinth when Modrinth hosts the exact same file.

## riven pin / unpin

```bash
riven pin sodium     # riven update leaves it alone
riven unpin sodium
```

## riven side

```bash
riven side xaeros-minimap client
```

Sets where an entry is installed: `client`, `server` or `both`.

## riven group

Optional groups are parts of a pack players can switch on or off, such as shaders or a minimap.

```bash
riven group add shaders --name "Shaders" --description "Iris + Complementary"
riven group add velocity --name "Velocity forwarding" --default
riven group set iris shaders
riven group set iris none       # take it out of any group
riven group rm shaders          # its entries become unconditional
```

| Option of `group add` | Description |
| --------------------- | ----------- |
| `--name <text>` | Display name (required) |
| `--description <text>` | Shown next to the switch |
| `--default` | Enabled unless the player opts out |

## riven list

```bash
riven list
riven list --tree       # explicit entries with what they require
riven list --outdated   # only entries with a newer compatible version
```

## riven why

```bash
riven why fabric-api
```

Shows every chain from an explicitly added entry down to this one.

## riven check

```bash
riven check
```

Validates `riven.json` and checks every mod's metadata against the others and the game: missing dependencies, version ranges, incompatibilities, duplicates and wrong loaders. It works offline from the content store and exits with code `1` when it finds a problem.

## riven bump

```bash
riven bump            # 1.4.0 → 1.4.1
riven bump minor      # 1.4.0 → 1.5.0
riven bump 2.0.0-beta.1
```

## riven import

```bash
riven import mrpack ./MyPack-1.2.0.mrpack
riven import mrpack https://example.com/pack.mrpack
riven import packwiz ./old-pack              # folder, pack.toml or its URL
```

Creates `riven.json`, `overrides/` and `local/` in the current directory. Files are identified on Modrinth by hash; CurseForge files from packwiz become links to the CurseForge CDN; anything unidentified embedded in the archive is kept under `local/`. Files that could not be handled are listed at the end. See [Migrating a pack](/docs/riven/guides/migrating).
