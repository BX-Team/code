A release is a folder of static files. Nothing has to run on the server: GitHub Pages, any web host or a CDN will do.

```
dist/
  channels/stable.json  + .sig     tiny pointer, checked on every launch
  channels/beta.json    + .sig
  releases/1.4.0.json   + .sig     self-contained manifest, never rewritten
  blobs/3f/3fa9c1…                 override files, named by their sha512
```

Mods are not copied into `dist/`: the manifest links them on Modrinth, GitHub or wherever they came from. Relative links resolve against the manifest, so `dist/` works under any address.

## riven keygen

```bash
riven keygen
```

Creates the pack's ed25519 signing key in `<config>/keys/<pack>.ed25519`, or shows the existing one. Back this file up — installed packs refuse releases signed with another key.

::callout{type="warning" title="Sign locally"}
  A key kept in CI secrets of the same GitHub repository only protects against tampering on the host or CDN. Build and sign on your own machine when you can.
::

## riven build

```bash
riven build                    # current version → dist/, channel stable
riven build --channel beta
riven build --unsigned
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `--channel <name>` | `stable` | Channel pointed at the new release |
| `--out <dir>` | `dist` | Output folder |
| `--unsigned` | | Build without a signature (no key needed) |

`build` refuses to overwrite a release that already exists with different content — `riven bump` first.

## riven publish

```bash
riven publish stable 1.4.0     # point stable at a built release
riven publish stable 1.3.2     # roll back
riven publish beta 1.5.0-beta.1
```

Moves a channel pointer to any release already in `dist/releases/`. Instances on that channel follow on their next launch. `--out` changes the folder.

## riven deploy

```bash
riven deploy
riven deploy --no-push
riven deploy --branch pages --remote upstream
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `--branch <name>` | `gh-pages` | Branch to commit to |
| `--remote <name>` | `origin` | Remote to push to |
| `--out <dir>` | `dist` | Folder to deploy |
| `--no-push` | | Only commit to the local branch |

Commits `dist/` on top of the branch without touching your working tree. Files only the branch has (older releases built on another machine) are kept and copied back into `dist/`; a published release or blob with different content is refused. For a GitHub remote it prints the Pages address and the short install link `gh:owner/repo`.

Turn on GitHub Pages for the branch once in the repository settings.

## riven export

```bash
riven export mrpack
riven export prism --side client
riven export riven --out ./MyPack.riven
```

| Format | Result |
| ------ | ------ |
| `mrpack` | Modrinth pack for any launcher that reads `.mrpack`; files from hosts Modrinth does not allow are embedded |
| `prism` | Prism / MultiMC instance zip with the right loader, client side by default |
| `riven` | `.riven` archive: the manifest plus its own files, mods linked — for sharing over Discord or a USB stick |

| Option | Description |
| ------ | ----------- |
| `--side <client\|server>` | Only content for this side |
| `--out <file>` | Output file; default `exports/<id>-<version>.<ext>` |
