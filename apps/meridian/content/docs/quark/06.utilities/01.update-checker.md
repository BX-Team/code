`quark-update` compares the running version with the newest release on Modrinth, Hangar, GitHub, SpigotMC, a Reposilite repository or any JSON endpoint. Add it with `quark { modules(QuarkModule.UPDATE) }`.

## Basic Usage

```java
@Override
public void onEnable() {
    Platform platform = PaperPlatform.create(this);

    UpdateChecker checker = new UpdateChecker(UpdateProvider.modrinth("my-plugin"), getPluginMeta().getVersion());
    checker.checkAndLog(platform.logger());
}
```

The check runs in the background and never blocks the server. `checkAndLog` prints a warning when a newer version exists or the check failed, and a debug message when the plugin is up to date:

```txt
[MyPlugin] A new version 1.2.0 is available (running 1.1.0): https://modrinth.com/project/my-plugin/version/a1B2c3D4
```

## Providers

| Provider | Example |
|----------|---------|
| Modrinth | `UpdateProvider.modrinth("my-plugin")` |
| Modrinth, only some loaders | `UpdateProvider.modrinth("my-plugin", "paper", "spigot")` |
| Hangar | `UpdateProvider.hangar("MyPlugin")` |
| GitHub Releases | `UpdateProvider.github("BX-Team", "MyPlugin")` |
| SpigotMC | `UpdateProvider.spigot(12345)` |
| Reposilite | `UpdateProvider.reposilite(URI.create("https://repo.bxteam.org"), "releases", "org.bxteam", "myplugin")` |
| Any JSON endpoint | `UpdateProvider.json(URI.create("https://api.example.com/version"), "latest.version")` |

- **Modrinth** takes the project id or slug and only counts versions of type *release*. With loaders, only versions published for one of them count, useful when the project ships separate Paper and Velocity builds. `new ModrinthProvider(project, true, loaders, executor)` also counts betas and alphas.
- **GitHub** takes the latest release; drafts and pre-releases are skipped and a leading `v` in the tag is ignored.
- **JSON** reads the version from a path in the response: dots for keys, brackets for array indexes (`version`, `data.latest.name`, `[0].tag`). A missing value means no release.

### Several Sources

`firstOf` asks providers in order and uses the first that answers. A failing or empty provider is skipped:

```java
UpdateProvider provider = UpdateProvider.firstOf(
        UpdateProvider.modrinth("my-plugin"),
        UpdateProvider.github("BX-Team", "MyPlugin")
);
```

### Using the Plugin's Scheduler

The factories run HTTP requests on a shared daemon thread. To use your plugin's scheduler instead, create the provider class directly with an `Executor`:

```java
UpdateProvider provider = new GitHubProvider("BX-Team", "MyPlugin", platform.scheduler().asExecutor());
```

## Notifying Players

The adapters can tell players with a permission about the update when they join. The notifier uses the result of the last finished check and never checks by itself, so run a check first:

::code-group
```java [Paper / Bukkit]
UpdateChecker checker = new UpdateChecker(UpdateProvider.modrinth("my-plugin"), getPluginMeta().getVersion());
checker.checkAndLog(platform.logger());
BukkitUpdateNotifier.register(this, checker, "myplugin.update");
```
```java [Velocity]
UpdateChecker checker = new UpdateChecker(UpdateProvider.modrinth("my-plugin"), "1.0.0");
checker.checkAndLog(platform.logger());
VelocityUpdateNotifier.register(server, this, checker, "myplugin.update");
```
```java [BungeeCord]
UpdateChecker checker = new UpdateChecker(UpdateProvider.modrinth("my-plugin"), getDescription().getVersion());
checker.checkAndLog(platform.logger());
BungeeUpdateNotifier.register(this, checker, "myplugin.update");
```
::

The default message is `[MyPlugin] A new version ... is available ...`. Pass your own as the last argument:

```java
BukkitUpdateNotifier.register(this, checker, "myplugin.update",
        outdated -> "§e[MyPlugin] §fVersion " + outdated.latest().version() + " is out, you run " + outdated.current());
```

On Velocity the message is an Adventure `Component`. `unregister()` stops the notifier.

## Periodic Checks

`check()` only checks once. Repeat it with the scheduler for servers that run for weeks:

```java
platform.scheduler().asyncRepeating(() -> checker.checkAndLog(platform.logger()), Duration.ZERO, Duration.ofHours(6));
```

## Handling the Result Yourself

`check()` returns a `CompletableFuture<UpdateStatus>` that never completes exceptionally. Failures become `UpdateStatus.Unknown`:

```java
checker.check().thenAccept(status -> {
    if (status instanceof UpdateStatus.Outdated outdated) {
        ReleaseInfo latest = outdated.latest();
        getLogger().info("Update " + latest.version() + " published at " + latest.publishedAt() + ": " + latest.url());
    } else if (status instanceof UpdateStatus.Unknown unknown) {
        getLogger().fine("Update check failed: " + unknown.cause());
    }
});

// the last result, without a new request
checker.lastStatus().ifPresent(status -> { /* ... */ });
```

| Status | Meaning |
|--------|---------|
| `UpToDate(current)` | The running version is the newest, or nothing is published |
| `Outdated(current, latest)` | A newer release exists. `describe()` gives a one-line message |
| `Unknown(cause)` | The check failed, for example the site was unreachable |

Versions are compared as [semantic versions](https://semver.org): `1.10.0` is newer than `1.9.0`, and `1.2.0-beta` is older than `1.2.0`.
