title: Plugin Descriptor
description: Generate plugin.yml, paper-plugin.yml, bungee.yml or velocity-plugin.json from the build script.
---

`quark { pluginYml { } }` writes the descriptor your server reads, so the name, version and main class live in the build script next to everything else. It replaces [plugin-yml](https://github.com/eldoriarpg/plugin-yml): one block for every platform, no extra Gradle plugin.

The file depends on `platform`:

| `platform` | File |
|------------|------|
| `PAPER`, `FOLIA`, `BUKKIT` | `plugin.yml` |
| `PAPER`, `FOLIA` with `paperPlugin()` | `paper-plugin.yml` |
| `BUNGEE` | `bungee.yml` |
| `VELOCITY` | `velocity-plugin.json` |

Generation is opt-in: without a `pluginYml { }` block nothing is written, and a hand-written `src/main/resources/plugin.yml` keeps working.

## Example

::code-group
```kotlin [Gradle Kotlin]
import org.bxteam.quark.gradle.ServerPlatform

version = "1.0.0"
description = "Says hello"

quark {
    platform = ServerPlatform.PAPER

    pluginYml {
        main = "com.example.ExamplePlugin"
        apiVersion = "1.20"
        authors("Me")
        website = "https://example.com"
        foliaSupported = true
        softDepend("PlaceholderAPI")

        commands {
            register("hello") {
                description = "Says hello"
                aliases("hi")
                permission = "example.hello"
                usage = "/<command> [player]"
            }
        }

        permissions {
            register("example.hello") { default = TRUE }
            register("example.admin") {
                default = OP
                children("example.hello")
            }
        }
    }
}
```
```groovy [Gradle Groovy]
version = '1.0.0'
description = 'Says hello'

quark {
    platform 'paper'

    pluginYml {
        main = 'com.example.ExamplePlugin'
        apiVersion = '1.20'
        authors 'Me'
        website = 'https://example.com'
        foliaSupported = true
        softDepend 'PlaceholderAPI'

        commands {
            register('hello') {
                description = 'Says hello'
                aliases 'hi'
                permission = 'example.hello'
                usage = '/<command> [player]'
            }
        }

        permissions {
            register('example.hello') { it.default = TRUE }
            register('example.admin') {
                it.default = OP
                children 'example.hello'
            }
        }
    }
}
```
::

The build writes this to `build/generated/quark/plugin-yml` and puts it into the jar:

```yaml [plugin.yml]
name: example
version: "1.0.0"
main: com.example.ExamplePlugin
description: Says hello
api-version: "1.20"
authors:
  - Me
website: "https://example.com"
softdepend:
  - PlaceholderAPI
folia-supported: true
commands:
  hello:
    description: Says hello
    aliases:
      - hi
    permission: example.hello
    usage: "/<command> [player]"
permissions:
  example.admin:
    default: op
    children:
      example.hello: true
  example.hello:
    default: true
```

Strings that YAML would read as something else are quoted: `1.20` would become the number `1.2`, `yes` a boolean.

::callout{type="info" title="Groovy and default"}
  `default` is a keyword in Groovy. Write `it.default = OP` or `setDefault(OP)` inside a permission.
::

## Options

| Option | Default | Platforms | Description |
|--------|---------|-----------|-------------|
| `name` | root project name | all | Plugin name |
| `version` | project version | all | Plugin version |
| `main` | required | all | Main class |
| `description` | project description | all | Description |
| `authors(...)` | none | all | Authors. `bungee.yml` gets them joined into `author` |
| `website` | not set | Bukkit, Paper, Velocity | Website, `url` in `velocity-plugin.json` |
| `depend(...)` | none | all | Plugins that must be present |
| `softDepend(...)` | none | all | Plugins loaded first when present |
| `loadBefore(...)` | none | Bukkit, Paper | Plugins loaded after this one |
| `apiVersion` | not set | Bukkit, Paper | Lowest API version, e.g. `"1.20"`. Required for `paper-plugin.yml` |
| `foliaSupported` | `true` with `platform = FOLIA` | Bukkit, Paper | Whether the plugin runs on Folia |
| `load` | not set | Bukkit, Paper | `LoadOrder.STARTUP` or `LoadOrder.POSTWORLD` (`import org.bxteam.quark.gradle.pluginyml.LoadOrder`); `load 'startup'` in Groovy |
| `contributors(...)` | none | Bukkit, Paper | Contributors |
| `prefix` | not set | Bukkit, Paper | Prefix of the plugin's log lines |
| `provides(...)` | none | Bukkit, Paper | Other plugin names this plugin answers to |
| `defaultPermission` | not set | Bukkit, Paper | Default of permissions that don't set one |
| `commands { }` | none | Bukkit | Commands, see below |
| `permissions { }` | none | Bukkit, Paper | Permissions, see below |
| `paperPlugin()` | off | Paper | Writes `paper-plugin.yml` instead of `plugin.yml` |
| `bootstrapper`, `loader` | not set | Paper plugin | `PluginBootstrap` and `PluginLoader` classes |
| `hasOpenClassloader` | not set | Paper plugin | Whether other plugins see your classes without depending on you |
| `id` | `name` in lower case, spaces as `-` | Velocity | Plugin id |
| `extra(key, value)` | none | all | A key this block has no option for |

A field a file has no key for is handled in one of two ways. Metadata such as `website` in `bungee.yml` is left out. A field that changes how the server loads the plugin, such as `commands` in `velocity-plugin.json` or `loadBefore` in `bungee.yml`, fails the build with a message, so a setting never disappears silently.

### Commands

| Option | Description |
|--------|-------------|
| `description` | Shown in `/help` |
| `aliases(...)` | Other names of the command |
| `permission` | Permission needed to run it |
| `permissionMessage` | Sent to players without the permission |
| `usage` | Shown when the executor returns `false`; `<command>` is replaced with the label |

Command names and aliases cannot contain `:` or spaces. A command without options is written as `hello: {}`, which is all Bukkit needs.

### Permissions

| Option | Description |
|--------|-------------|
| `description` | Description |
| `default` | `TRUE` (everyone), `FALSE` (no one), `OP` or `NOT_OP`. The server's default is `OP` |
| `children(...)` | Child permissions granted with this one |
| `children.put(name, false)` | A child permission revoked with this one |

## Dependencies on Other Plugins

Declare them once with `depend`, `softDepend` and `loadBefore`, the plugin writes them in the shape of each file:

| | `plugin.yml` | `paper-plugin.yml` | `bungee.yml` | `velocity-plugin.json` |
|-|--------------|--------------------|--------------|------------------------|
| `depend("X")` | `depend` | `server.X: {load: BEFORE, required: true}` | `depends` | `{id: X, optional: false}` |
| `softDepend("X")` | `softdepend` | `server.X: {load: BEFORE, required: false}` | `softDepends` | `{id: X, optional: true}` |
| `loadBefore("X")` | `loadbefore` | `server.X: {load: AFTER, required: false}` | not supported | not supported |

Libraries are not listed: dependencies of the `quark` configuration are downloaded by Quark at runtime, see [Loading Dependencies](/docs/quark/dependencies/loading-dependencies). There is no `libraries` section and no `paper-libraries.json`.

## Paper Plugins

`paperPlugin()` switches Paper and Folia to `paper-plugin.yml`:

```kotlin
quark {
    platform = ServerPlatform.PAPER

    pluginYml {
        paperPlugin()
        main = "com.example.ExamplePlugin"
        bootstrapper = "com.example.ExampleBootstrap"
        apiVersion = "1.21"
        depend("Vault")
    }
}
```

`paper-plugin.yml` has no `commands` section. Register commands in code with `LifecycleEvents.COMMANDS`; `commands { }` together with `paperPlugin()` fails the build.

## Velocity

On Velocity the descriptor usually comes from the `@Plugin` annotation, written by `annotationProcessor("com.velocitypowered:velocity-api:...")`. Use either the annotation processor or `pluginYml { }`, not both. With both, two `velocity-plugin.json` files end up in the build: the Shadow jar quietly keeps the one from `@Plugin` and ignores `pluginYml { }`, and the plain `jar` task fails with "Entry velocity-plugin.json is a duplicate". To use `pluginYml { }`, remove the `annotationProcessor` dependency; the `@Plugin` annotation itself can stay.

```kotlin
quark {
    platform = ServerPlatform.VELOCITY

    pluginYml {
        id = "example"
        name = "Example"
        main = "com.example.ExamplePlugin"
        depend("luckperms")
    }
}
```

Velocity ids are lowercase letters, digits, `-` and `_`, starting with a letter.

## Other Keys

`extra` writes a key this block has no option for, after the generated ones. The value can be a string, a boolean, a number or a list of strings:

```kotlin
pluginYml {
    extra("paper-skip-libraries", true)
}
```

A key the block already writes, such as `extra("main", ...)`, fails the build; use the option instead.

## Migrating from plugin-yml

1. Remove `id("de.eldoria.plugin-yml.bukkit")` (or `net.minecrell.plugin-yml.*`) and its version from the version catalog.
2. Move the content of `bukkit { }`, `paper { }` or `bungee { }` into `quark { pluginYml { } }` and drop the `BukkitPluginDescription` import.
3. Replace `authors = listOf(...)` with `authors(...)`, `BukkitPluginDescription.Permission.Default.OP` with `OP`, `depend = listOf(...)` with `depend(...)`, and so on.
4. Move `library(...)` dependencies to `quark(...)`.

::code-group
```kotlin [Before]
import net.minecrell.pluginyml.bukkit.BukkitPluginDescription

plugins {
    id("de.eldoria.plugin-yml.bukkit") version "0.9.0"
}

bukkit {
    name = "Example"
    main = "com.example.ExamplePlugin"
    apiVersion = "1.16"
    authors = listOf("Me")
    foliaSupported = true

    permissions {
        register("example.reload") {
            default = BukkitPluginDescription.Permission.Default.OP
        }
    }
}
```
```kotlin [After]
quark {
    platform = ServerPlatform.PAPER

    pluginYml {
        name = "Example"
        main = "com.example.ExamplePlugin"
        apiVersion = "1.16"
        authors("Me")
        foliaSupported = true

        permissions {
            register("example.reload") { default = OP }
        }
    }
}
```
::

Applying plugin-yml and using `pluginYml { }` at the same time fails the build, because both would write the same file. The same goes for a hand-written `src/main/resources/plugin.yml` next to the block: delete one of them.

::callout{type="warning" title="Check description"}
  `name`, `version` and `description` now default to the project's values. In `gradle.properties` write `description=My plugin` without quotes, otherwise the quotes end up in the description.
::
