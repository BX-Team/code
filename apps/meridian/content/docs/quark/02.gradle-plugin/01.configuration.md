The `org.bxteam.quark` plugin is the glue between your build and Quark. When you apply it, it:

- adds the BX Team repository, the Quark BOM, the adapter of `platform` and the modules you list;
- adds the `quark` configuration for libraries downloaded at runtime and writes them, with repositories and relocations, to `META-INF/quark/manifest` inside your jar;
- relocates Quark to `<group>.libs.quark` in the Shadow jar, plus your own `relocate(...)` rules;
- registers dev servers, see [Dev Servers](/docs/quark/gradle-plugin/dev-servers);
- generates `plugin.yml` and the other plugin descriptors from `pluginYml { }`, see [Plugin Descriptor](/docs/quark/gradle-plugin/plugin-yml).

The plugin requires Shadow (`com.gradleup.shadow`) in the same project and works on Gradle 8.14 and newer, with the configuration cache.

## Full Example

::code-group
```kotlin [Gradle Kotlin]
import org.bxteam.quark.gradle.QuarkModule
import org.bxteam.quark.gradle.ServerPlatform
import org.bxteam.quark.gradle.relocate

quark {
    platform = ServerPlatform.PAPER
    modules(QuarkModule.DEPENDENCY, QuarkModule.CONFIG, QuarkModule.UPDATE)

    // where the server downloads runtime dependencies from
    repositories {
        maven("https://repo.bxteam.org/releases")
        includeProjectRepositories()
    }

    // applied to the Shadow jar and to dependencies loaded at runtime
    relocate("com.zaxxer.hikari", "com.example.libs.hikari")

    // writes plugin.yml
    pluginYml {
        main = "com.example.ExamplePlugin"
        apiVersion = "1.20"
    }

    devServer {
        version = "1.21.8"
        acceptEula()
    }
}

dependencies {
    quark("com.zaxxer:HikariCP:7.1.0")
    quark("com.google.code.gson:gson:2.11.0") { relocate = true }
}
```
```groovy [Gradle Groovy]
quark {
    platform 'paper'
    modules 'dependency', 'config', 'update'

    // where the server downloads runtime dependencies from
    repositories {
        maven 'https://repo.bxteam.org/releases'
        includeProjectRepositories()
    }

    // applied to the Shadow jar and to dependencies loaded at runtime
    relocate 'com.zaxxer.hikari', 'com.example.libs.hikari'

    // writes plugin.yml
    pluginYml {
        main = 'com.example.ExamplePlugin'
        apiVersion = '1.20'
    }

    devServer {
        version = '1.21.8'
        acceptEula()
    }
}

dependencies {
    quark 'com.zaxxer:HikariCP:7.1.0'
    quark('com.google.code.gson:gson:2.11.0') { ext.relocate = true }
}
```
::

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `platform` | not set | The server the plugin targets: `PAPER`, `FOLIA`, `BUKKIT`, `VELOCITY` or `BUNGEE`. Adds the adapter and selects the default server of dev servers |
| `modules(...)` | none | Optional modules, see [Modules](/docs/quark/getting-started/installation#modules) |
| `repositories { }` | Google Maven Central mirror | Repositories the server downloads `quark` dependencies from. A `repositories { }` block replaces the default |
| `relocate(from, to)` | none | Relocates a package in the Shadow jar and in dependencies loaded at runtime |
| `relocateQuark` | `true` | Whether Quark itself is relocated in the Shadow jar |
| `quarkPackage` | `<group>.libs.quark` | Package Quark is relocated to |
| `librariesPackage` | `<group>.libs` | Package that dependencies marked with `relocate = true` are moved into |
| `pluginYml { }` | not generated | The plugin descriptor of `platform`, see [Plugin Descriptor](/docs/quark/gradle-plugin/plugin-yml) |

In Groovy, `platform` and `modules` also accept names: `platform 'paper'`, `modules 'dependency', 'config-validator'`. Names ignore case and accept hyphens.

## Runtime Dependencies

Dependencies in the `quark` configuration are resolved by Gradle when you build, and the whole tree, with the versions Gradle chose, is written to the manifest. The server downloads exactly that list; POMs are not resolved a second time, so a version you forced in Gradle stays forced at runtime.

The `quark` configuration extends `compileOnly`, so the libraries are on your compile class path but not in the jar. Exclusions and constraints work like in any other configuration:

::code-group
```kotlin [Gradle Kotlin]
dependencies {
    quark("com.google.inject:guice:7.0.0") {
        exclude("com.google.guava", "guava")
    }
}
```
```groovy [Gradle Groovy]
dependencies {
    quark('com.google.inject:guice:7.0.0') {
        exclude group: 'com.google.guava', module: 'guava'
    }
}
```
::

Load the manifest in your plugin with `LibraryManager#loadFromGradle()`, see [Loading Dependencies](/docs/quark/dependencies/loading-dependencies).

### Repositories

By default the server downloads from the [Google mirror of Maven Central](https://maven-central.storage-download.googleapis.com/maven2/). A `repositories { }` block replaces this list:

```kotlin
quark {
    repositories {
        maven("https://maven-central.storage-download.googleapis.com/maven2/")
        maven("https://jitpack.io/")

        // also use every http(s) Maven repository of this project
        includeProjectRepositories()
    }
}
```

`includeProjectRepositories()` adds the remote repositories declared in the project's `repositories { }`. Local repositories such as `mavenLocal()` are skipped, the server cannot reach them.

## Relocation

Quark is always relocated into your plugin. It moves `org.bxteam.quark` to `<group>.libs.quark`, so a plugin with Quark 2.0.0 and another one with Quark 2.1.0 never load each other's classes. Disable it with `relocateQuark = false` only if you relocate Quark yourself.

For your own libraries there are two ways.

### `relocate = true`

Marks one `quark` dependency for relocation. The plugin reads the packages from the library jar and moves each of them under `librariesPackage`, keeping the original name: `com.google.gson` becomes `com.example.libs.com.google.gson`.

::code-group
```kotlin [Gradle Kotlin]
import org.bxteam.quark.gradle.relocate

dependencies {
    quark("com.google.code.gson:gson:2.11.0") { relocate = true }
}
```
```groovy [Gradle Groovy]
dependencies {
    quark('com.google.code.gson:gson:2.11.0') { ext.relocate = true }
}
```
::

Use it for libraries the server may already ship in another version, such as Gson, Guava, SnakeYAML or Adventure. The plugin then always uses its own version.

### `relocate(from, to)`

An explicit rule for a package. It is applied to the Shadow jar and to every dependency loaded at runtime:

```kotlin
quark {
    relocate("com.zaxxer.hikari", "com.example.libs.hikari")
}
```

Either way your code is compiled against the original package, and Shadow rewrites your classes to the relocated one. Read [Relocation](/docs/quark/dependencies/relocation) for how the runtime side works.

## Tasks

| Task | Description |
|------|-------------|
| `generateQuarkManifest` | Writes `META-INF/quark/manifest` to `build/generated/quark/resources`. Runs before `processResources` |
| `collectRelocatedQuarkLibraries` | Finds the packages of dependencies marked with `relocate = true` |
| `generatePluginYml` | Writes the plugin descriptor from `pluginYml { }` to `build/generated/quark/plugin-yml`. Writes nothing without the block |
| `runServer`, `run<Name>Server` | Start [dev servers](/docs/quark/gradle-plugin/dev-servers) |

You never call the first three by hand, the build runs them.

## The Manifest

The manifest is a small text file. You don't need to edit it, but it helps when you debug what the server downloads:

```ini [META-INF/quark/manifest]
# Quark dependency manifest, generated by the Quark Gradle plugin
format=1

[repositories]
https://maven-central.storage-download.googleapis.com/maven2/

[dependencies]
com.zaxxer:HikariCP:7.1.0
com.google.code.gson:gson:2.11.0

[relocations]
com.google.gson=com.example.libs.com.google.gson
```
