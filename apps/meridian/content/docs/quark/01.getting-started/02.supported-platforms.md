Every server has its own adapter. It implements the `Platform` and `Scheduler` API, adds downloaded libraries to the plugin's class loader and registers the update notifier.

| `ServerPlatform` | Adapter | Runs on | Built against |
|------------------|---------|---------|---------------|
| `PAPER` | `quark-paper` | Paper and its forks (Purpur, DivineMC, Pufferfish, Leaf, ...) | Paper API `1.20.1` |
| `FOLIA` | `quark-paper` | Folia and its forks (Canvas) | Paper API `1.20.1` |
| `BUKKIT` | `quark-bukkit` | Spigot, CraftBukkit and any Bukkit-compatible server | Spigot API `1.19.4` |
| `VELOCITY` | `quark-velocity` | Velocity | Velocity API `3.1.1` |
| `BUNGEE` | `quark-bungee` | BungeeCord and Waterfall | BungeeCord API `1.19` |

The server has to run on Java 17 or newer, every Quark module is built for it.

::callout{type="info" title="How to use it?"}
  Set `quark { platform = ServerPlatform.PAPER }` and the Gradle plugin adds the right adapter. See the [Installation](/docs/quark/getting-started/installation) page for more information.
::

## Paper or Bukkit?

Use `PAPER` for anything that runs Paper, even if your plugin only uses the Bukkit API. `quark-paper` contains `quark-bukkit` and adds:

- support for `paper-plugin.yml` plugins, whose libraries live in a separate class loader;
- the region scheduler on Folia, with `sync(entity, ...)` and `sync(location, ...)` overloads.

Use `BUKKIT` only for plugins that must also run on Spigot. On Folia the Bukkit adapter refuses to start, because Folia has no Bukkit scheduler.

## Folia

`FOLIA` uses the same adapter as `PAPER`; it only makes dev servers start Folia by default. Quark's scheduler picks the region scheduler on its own whenever the server has one, so a single jar works on both Paper and Folia.

Keep in mind that `Scheduler#sync(...)` on Folia runs on the **global region** thread. That is safe for plugin state, game rules and console commands, but not for entities or blocks. Read [Scheduler](/docs/quark/platform/scheduler#folia) for the entity and location overloads.

## Proxies

Velocity and BungeeCord have no main thread, so "sync" tasks of the scheduler run on the proxy's task pool. `PlatformVersion#minecraft()` is `null` on proxies, since they support a range of Minecraft versions.

## Sponge and Fabric

Quark 1.x had Sponge and Fabric adapters. Quark 2.0 does not have them yet; plugins and mods for these platforms should stay on Quark 1.3.
