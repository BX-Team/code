Quark downloads dependencies from Maven repositories over HTTP. With the Gradle plugin the repositories come from the manifest, see [Repositories in the Gradle plugin](/docs/quark/gradle-plugin/configuration#repositories). Dependencies you load by hand use the repositories added to the library manager.

## Built-in Repositories

```java
// Google mirror of Maven Central (recommended)
libraryManager.addGoogleMavenCentralMirror();

// JitPack, builds Git repositories on demand
libraryManager.addJitPack();

// Sonatype OSS
libraryManager.addSonatype();

// the local Maven repository of the user running the server (~/.m2/repository)
libraryManager.addMavenLocal();
```

The same URLs are available as constants in `Repositories`, for example `Repositories.GOOGLE_MAVEN_CENTRAL_MIRROR`.

::callout{type="warn" title="Don't use Maven Central directly"}
  Using `repo1.maven.org` as a download source for servers is against the [Maven Central Terms of Service](https://central.sonatype.org/terms/). `addMavenCentral()` is deprecated and Quark logs a warning when a repository points there. Use `addGoogleMavenCentralMirror()` instead.
::

## Custom Repositories

```java
libraryManager.addRepository("https://repo.bxteam.org/releases");
libraryManager.addRepository("https://repo.papermc.io/repository/maven-public/");
```

## Fallback Repository

A dependency can name one extra repository, tried after all global ones. Useful when only one library comes from a special place:

```java
Dependency dependency = Dependency.of("com.example", "library", "1.0.0")
        .withFallbackRepository("https://repo.example.com/releases/");

libraryManager.loadDependency(dependency);
```

## Lookup Order

1. The local cache in `<dataDirectory>/libs`. A JAR that was downloaded once is never downloaded again.
2. The global repositories, in the order they were added.
3. The fallback repository of the dependency, if it has one.

```java
for (Repository repository : libraryManager.getRepositories()) {
    getLogger().info("Repository: " + repository.getUrl());
}
```

## Troubleshooting

- **Dependency not found**: check the coordinates and that one of the repositories hosts the artifact. With `libraryManager.setLogLevel(LogLevel.DEBUG)` every repository that was tried is logged.
- **Connection timeouts**: the server may have no outbound internet access. Pre-fill `<dataDirectory>/libs` with the JARs and POMs in Maven layout (`com/zaxxer/HikariCP/7.1.0/HikariCP-7.1.0.jar`), Quark uses them without connecting.
- **Private repositories**: repositories that need credentials are not supported. Publish runtime dependencies to a public repository or shade them.
