New options need no migration: missing keys are added with their defaults on the next load. A migration is only needed when an existing key changes its name, place or format, so the server owner's value survives the update.

## Versioning a Config

Give the class a version with `@ConfigVersion` and add one `Migration` per step:

```java
@ConfigVersion(3)
@NameStrategy(NameStyle.HYPHEN_CASE)
public class PluginConfig extends QuarkConfig {
    public Messages messages = new Messages();
    public Duration cooldown = Duration.ofSeconds(30);

    public static class Messages {
        public String prefix = "<gray>[MyPlugin]</gray> ";
    }
}
```

```java
config = QuarkConfig.create(PluginConfig.class, options -> options
        .file(folder.resolve("config.yml"))
        .migrations(
                // 1 -> 2: prefix moved into the messages section
                Migration.of(1, 2, root -> root.node("prefix").moveTo(root.node("messages", "prefix"))),
                // 2 -> 3: cooldown-seconds: 30 became cooldown: 30s
                Migration.of(2, 3, root -> {
                    ConfigNode old = root.node("cooldown-seconds");
                    if (!old.isVirtual()) {
                        root.node("cooldown").set(old.getInt(30) + "s");
                        old.remove();
                    }
                })
        ));
config.load();
```

The version is stored in the file under `config-version`:

```yaml
config-version: 3
messages:
  prefix: '<gray>[MyPlugin]</gray> '
cooldown: 30s
```

## How Migrations Run

- A file without `config-version` has version 1, so the first release of a config needs no annotation.
- A new file is created with the current version, no migration runs.
- An older file runs every step from its version up to the current one, in order. Each step is logged: `Migrated config.yml from version 1 to 2`.
- Migrations edit the raw tree before it is bound to the class, so they work with keys as they are in the file, not with fields.
- A missing step, a failing step, or a file newer than the plugin fails the load. The file is left untouched and the server owner is told to update the plugin or restore a backup.

Use a custom key with `@ConfigVersion(value = 2, key = "version")`. The key is reserved, don't bind a field to it.

## ConfigNode

`ConfigNode` is the tree between the file and your class. Migrations and serializers work on it.

```java
ConfigNode host = root.node("database", "host");   // never null
if (host.isVirtual()) {
    // the key does not exist in the file
}

String value = host.getString("localhost");         // with a default
int port = root.node("database", "port").getInt(3306);

root.node("database", "pool-size").set(10);         // creates the key
root.node("old-key").moveTo(root.node("new-key"));  // rename, keeps the comment
root.node("removed-option").remove();
```

| Method | Description |
|--------|-------------|
| `node(String...)` | Child by path. Missing children are *virtual* until a value is set |
| `isVirtual()`, `isNull()`, `isMap()`, `isList()`, `isScalar()` | What the node holds |
| `getString()`, `getInt(def)`, `getLong(def)`, `getDouble(def)`, `getBoolean(def)` | Read a scalar |
| `set(Object)` | Set a value: scalars, maps, lists or another node |
| `setMap()`, `setList()`, `appendElement()` | Build sections and lists |
| `children()`, `elements()` | Children of a section or a list |
| `moveTo(ConfigNode)` | Move the value and comment to another node |
| `remove()` | Remove the node from its parent |
| `copy()`, `raw()` | Deep copy, or plain Java maps and lists |
| `comment(...)`, `comment()` | Comment lines above the key |
| `path()`, `pathString()`, `key()`, `parent()` | Where the node is |

## Writing Good Migrations

- Check `isVirtual()` before moving or converting: a server owner may have removed the key.
- Only touch what changed. Everything else is filled in from the defaults afterwards.
- Keep old migrations. A server can skip several plugin versions and must still go through every step.
- Bump `@ConfigVersion` in the same release as the migration that needs it.
