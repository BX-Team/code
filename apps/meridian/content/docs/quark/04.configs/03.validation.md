`quark-config-validator` checks values when a config loads. Add it with `quark { modules(QuarkModule.CONFIG_VALIDATOR) }`; it registers itself, every config uses it.

## Annotations

```java
public class PluginConfig extends QuarkConfig {
    @NotNull
    @Pattern("[a-z0-9_]{3,16}")
    public String serverId = "lobby_1";

    @Min(1) @Max(100)
    public int maxHomes = 3;

    @Min(value = 0.0, message = "can't be negative")
    public double startBalance = 100.0;

    @Pattern(value = "#[0-9a-fA-F]{6}", message = "must be a hex color like #ff8800")
    public List<String> colors = List.of("#ff8800", "#00aaff");

    @Check(value = EvenNumber.class, message = "must be even")
    public int slots = 4;

    public static final class EvenNumber implements Predicate<Integer> {
        @Override
        public boolean test(Integer value) {
            return value == null || value % 2 == 0;
        }
    }
}
```

| Annotation | Applies to | Checks |
|------------|------------|--------|
| `@NotNull` | any field | The value is not `null` (`~` or `null` in the file) |
| `@Min(value)` | numbers of any type | The value is at least `value` |
| `@Max(value)` | numbers of any type | The value is at most `value` |
| `@Pattern(regex)` | strings, collections of strings | The whole string matches. On a collection every element must match |
| `@Check(Predicate.class)` | any field | A custom predicate returns `true`. Repeatable |

Every annotation has a `message`. In `@Min`, `@Max` and `@Pattern`, `{value}` is replaced by the limit or the expression.

`@Min`, `@Max`, `@Pattern` and `@Check` accept `null`, so combine them with `@NotNull` where a value is required. The predicate of `@Check` needs a no-argument constructor and also receives `null`.

## What Happens on a Failure

Validation runs on every field of the config and of its nested objects, after the file is read and before any value reaches your config. If a check fails:

- `load()` and `reload()` throw `ConfigValidationException`;
- the exception lists **every** violation, not just the first one;
- your config keeps its previous values and the file is not touched.

```java
try {
    config.reload();
} catch (ConfigValidationException e) {
    getLogger().warning(e.getMessage());
}
```

```txt
Invalid configuration /plugins/MyPlugin/config.yml:
  - max-homes: must be at most 100
  - colors: must be a hex color like #ff8800
```

`e.violations()` returns them as a list of `Violation(path, message)` records, for example to send each one to the player who ran the reload command.

On the first start, when the plugin can't run with an invalid config, disable it with a clear message instead of a stack trace:

```java
try {
    config.load();
} catch (ConfigException e) {
    getLogger().severe(e.getMessage());
    getServer().getPluginManager().disablePlugin(this);
    return;
}
```

## Custom Validators

A `ConfigValidator` sees every field with its loaded value and returns violation messages. Register it in the options, or as a service in `META-INF/services/org.bxteam.quark.config.validation.ConfigValidator` to apply it to every config:

```java
public final class NoTabsValidator implements ConfigValidator {
    @Override
    public List<String> validate(Field field, Object value) {
        if (value instanceof String string && string.contains("\t")) {
            return List.of("must not contain tabs");
        }
        return List.of();
    }
}

config = QuarkConfig.create(PluginConfig.class, options -> options
        .file(folder.resolve("config.yml"))
        .validator(new NoTabsValidator()));
```

Custom validators work without `quark-config-validator`; the module only adds the annotations.
